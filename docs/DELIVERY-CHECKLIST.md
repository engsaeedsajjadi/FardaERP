# چک‌لیست تست نهایی پیش از تحویل — FardaERP

این چک‌لیست برای تست نهایی روی سیستم خودتان، بعد از اصلاحات ۱۹ نوامبر ۲۰۲۶ (CORE-016، SEC-1..3، PAY-1، UI-1..3) نوشته شده. جزئیات فنی هر اصلاح در `docs/CORE-CHANGES.md` آمده است.

> این اصلاحات با خواندن کد، اجرای `hooks.py` و تست‌های JS بررسی شده‌اند، اما استک کامل Docker و مرورگر هنوز روی سیستم واقعی اجرا نشده‌اند. هدف این چک‌لیست همین اجراست.

## ۱. دریافت کد

اگر نسخه‌ای از قبل دارید:

```bash
git fetch origin
git checkout arena/01a0a51f-fardaerp
git pull origin arena/01a0a51f-fardaerp
```

اگر نسخه‌ی قبلی را به‌صورت zip گرفته‌اید، یک clone تازه بگیرید:

```bash
git clone --branch arena/01a0a51f-fardaerp https://github.com/engsaeedsajjadi/FardaERP.git
```

## ۲. تنظیم `.env`

```bash
cp .env.example .env
```

- `DB_ROOT_PASSWORD` و `DB_PASSWORD` را با مقدار قوی پر کنید (`openssl rand -hex 24`).
- `FARDA_OTP_PEPPER` را پر کنید (`openssl rand -hex 32`). بدون آن OTP کار نمی‌کند.
- برای تست، `FARDA_PAYMENT_SANDBOX=1` و `FARDA_SMS_PROVIDER=console` بمانند.
- اگر `.env` قدیمی دارید، بخش «FardaERP integrations» را از `.env.example` به آن اضافه کنید.

## ۳. ساخت و اجرا

ایمیج حتماً از نو ساخته شود، چون مسیر فایل‌های UI عوض شده:

```bash
docker compose build --no-cache
docker compose up -d
```

**سایت جدید:**

```bash
docker compose exec backend bench new-site <SITE_NAME> \
  --db-root-username root --mariadb-user-host-login-scope=% \
  --mariadb-root-password <DB_ROOT_PASSWORD> --db-password <DB_PASSWORD> \
  --admin-password <رمز قوی> --install-app erpnext --install-app hrms
```

> `--db-root-username root` جلوی سؤال «Enter mysql super user» را می‌گیرد (جواب درست `root` است). `--mariadb-user-host-login-scope=%` لازم است تا workers و scheduler هم بتوانند به دیتابیس وصل شوند.

## ۶. پیش از تحویل نهایی (با دادهٔ واقعی)

این موارد هنوز باز هستند و باید به کارفرما اعلام شوند:

1. **درگاه پرداخت واقعی:** تست با کلید production و `FARDA_PAYMENT_SANDBOX=0`. در کد IDPay، فیلد `order_id` در مرحلهٔ verify خالی ارسال می‌شود و باید با کلید واقعی بررسی شود.
2. **پنل پیامک واقعی:** تست ارسال با کلید یکی از سرویس‌دهنده‌ها.
3. **سامانهٔ مؤدیان:** پیاده‌سازی نشده است.
4. **ورود با OTP:** فقط تأیید شماره پیاده شده و هنوز کاربر را وارد سیستم نمی‌کند.
5. **بکاپ:** اجرای `scripts/backup.sh` و یک بار `scripts/restore.sh` روی سایت آزمایشی.
6. **CI:** ورک‌فلوی GitHub فعال نیست (`scripts/ci/github-workflow.yml` آماده است).
